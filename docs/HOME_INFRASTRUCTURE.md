## Голос и аэронавтика

| Порт VPS | Назначение | Проверка |
|---|---|---|
| TCP25565 | Minecraft | Настоящий шифрованный login protocol767 |
| UDP25565 | Sable2.0.6 | Реальный декодер принял целые кадры55 и1856 байт |
| UDP24454 | Simple Voice Chat | 3 настоящих UDP ping/pong,94–125мс |

У принятого Sable UDP использует **тот же номер25565**, что Minecraft TCP.
Другой произвольный порт для Aeronautics не открывался. Sable проверяет UDP
challenge, связанный с TCP-соединением; unauthenticated UDP не выдаёт управление
кораблём. Полёт настоящего корабля с авторизованным клиентом ещё не проверен.

Simple Voice Chat **2.6.22**, NeoForge1.21.1, Modrinth version`2s7zUspF`:
SHA256`63116a4d21bd57221482d971dd85822f7c723c210b60411670cdb0aa26873cac`.
Это стабильный release; предлагаемая upstream2.6.24 для этой версии Minecraft
помечена beta. Клиент скачивает оригинал из Modrinth; ARR-файл не зеркалируется.
Конфигурация сервера: `data/config/voicechat/voicechat-server.properties`,
`voice_host=mc.erezcraft.com:24454`, обычная дальность48, шёпот24, MTU1275,
`force_voice_chat=false`. Проверка UDP не проверяет микрофон, захват/кодирование
аудио или разговор двух людей.

FRP: `frps-minecraft.service`, `/etc/frp-minecraft/frps.toml`, домашний
`/opt/minecraft/config/frpc-erezcraft.toml`; TLS/QUIC UDP51880.
`maxPortsPerClient=3`, allowPorts только25565/24454, `udpPacketSize=65535`
на обеих сторонах. Это устраняет прежнее ограничение FRP1500; наблюдаемый
native receive buffer Sable2048 не выдаётся за поддержку произвольных размеров.
Старый NAT UDP25565→WireGuard обходится узкими правилами нашего назначения.
Персистентный `erezcraft-game-ports.service` не очищает общую таблицу firewall.
Посторонний legacy frps7000 не менялся. RCON наружу не опубликован.

На macOS отдельно остаётся поддержка системного разрешения микрофона в нашем
лаунчере: нужен usage description и запрос разрешения в подписанном/собранном
app bundle, затем проверка реальным пользователем. В 0.4.1 такой запрос не
реализован; серверный UDP-тест не доказывает работоспособность голоса на Mac.
[Требование автора](https://modrepo.de/minecraft/voicechat/wiki/macos).

## EREZ ID и доступ

На первоначальном закрытом тесте: `online-mode=true`, `enforce-secure-profile=true`, whitelist=true. Были разрешены
канонический UUID владельца `_NaveL_IL` и отдельный тестовый профиль. По прямому поручению владельца OP4 выдана только его UUID;
других операторов нет.
Перенос файлов в другой лаунчер сам по себе доступа не даёт. Свой действующий
EREZ ID может использовать совместимый клиент; секретом не считается имя EXE.

authlib6.0.54 использует `POST /services/minecraft/profile/lookup/bulk/byname`.
Gateway теперь точно сопоставляет этот маршрут и документированный injector
alias с Drasl `/account/profiles/minecraft`, сохраняя закрытый список маршрутов.
Иначе штатный whitelist lookup не находил существующего игрока. Исправление
развёрнуто без замены БД, master key или UUID.

Проверены настоящее RSA/AES шифрование login, пропущенный/неверный/отозванный
токен, чужое имя и UUID, правильный профиль и отказ при недоступности auth.
Drasl принимает selectedProfile с чужим UUID с HTTP204, но возвращает серверу
канонический UUID владельца токена: подмена персонажа не происходит. Нельзя
описывать это как HTTP403. Отключение auth имитировалось только внутри нашего
Minecraft-контейнера и полностью отменено. Пароли/сессии владельца не применялись.
LoginSuccess до NeoForge configuration не является полным входом модпака.

## Резервное копирование на ПК владельца

По решению владельца архивы сохраняются **на этом Windows ПК**,
`D:\EREZCRAFT\backups`, а не на VPS. Папка закрыта owner-only ACL.
Диск D: на момент настройки имеет около775GB свободного места.

Домашний backup-контейнер каждый час выполняет save-off → save-all flush →
архив → save-on. Только **2 завершённых исходных архива**/максимум1день (`PRUNE_BACKUPS_COUNT=3`, включая latest symlink) остаются
на VM как источник копирования. Перезапущен только backup-sidecar; игровой JVM
и пользовательская игра не закрывались. Рабочий мир не менялся тестовой сценой.

Windows Task Scheduler **EREZCRAFT Backups** запускает
`D:\EREZCRAFT\backup-tools\runtime\pythonw.exe` с `backup_pc.py` рядом.
Отдельный stdlib-only Python3.12.14 скопирован в эту постоянную папку, не зависит
от срока жизни кеша Codex. Задача запускается раз в час и при входе Dimon,
StartWhenAvailable, повторы ошибок, лимит15минут, без окна, без admin прав,
без сохранённого пароля. Проверен настоящий фоновый запуск, LastTaskResult=0,
в отключённой сессии Dimon. **Interactive logon:** после полного выхода Dimon
из Windows задача не работает; следующий вход запускает догоняющую проверку.
Выключенный/спящий ПК также не копирует данные.

Мир хранится в `backups/world`: максимум72 архива и100GiB суммарно,
10GiB свободного места всегда резервируются; максимальный принимаемый архив16GiB.
Auth — `backups/auth`,28 копий; новая consistent snapshot не чаще чем раз6часов,
либо сразу при обнаружении пропавшей/повреждённой локальной копии.
`state.json` и вращаемый `backup.log` содержат состояние, размеры и хеши, без
учётных данных. Прежние файлы проверяются по байтам, не только по записи state.

Оба вида архивов шифруются **CMS AES-256-GCM / RSA-OAEP SHA256, RSA4096**.
На VM и VPS находится только публичный сертификат. Закрытый ключ восстановления:
`D:\EREZCRAFT\private\backup-recipient.key`, сертификат рядом `.crt`.
Ключ закрыт owner-only ACL; не заменять его и не загружать на серверы.
Без него копии не расшифровать; отдельная офлайн-копия ключа нужна владельцу.

Два отдельных SSH-ключа ПК имеют forced command и закреплённые host keys.
Домашний ключ разрешает только world-info/download-world: выбирается завершённый
архив из фиксированного каталога, проверяется gzip и создаётся временный ciphertext.
VPS-ключ разрешает только download-auth. Узкая sudoers-запись запускает **ровно**
root-owned Python snapshot program с фиксированным --stream; никакого произвольного
shell, SFTP, пути или recipient в запросе нет. Приём/upload архивов на VPS удалён.
Отказы для shell, upload и дополнительных аргументов проверены реальными ключами.

Auth snapshot использует SQLite backup API (включая WAL) и integrity_check,
копирует стабильные DB/master/signing keys/скины/config/app и шифрует их перед
выдачей. Временные файлы на VPS имеют права root-only и удаляются после отправки.
Сервис аккаунтов не останавливается. Неизменность ключей/UUID сохраняется.

Прежний VPS backup timer отключён и удалён, домашний VPS-upload cron удалён,
три созданных нами VPS ciphertext-файла удалены после успешной новой PC-проверки.
VPS не хранит резервные архивы мира/EREZ ID. Старые конфигурационные rollback
копии других развёртываний и рабочая база аккаунтов не удалялись.
Расширение VPS ради резервных архивов больше не требуется; на нём около2.6GB
свободно. Health reserve VPS теперь2GiB для его текущей роли без world archives;
на домашнем диске остаётся5GiB. Рост остальных сервисов всё равно надо отслеживать.

Репетиция **нового PC-потока**: обе копии скачаны ограниченными ключами,
проверены authenticated decryption,16 файлов auth по manifest, SQLite integrity,
master/signing keys и12 FULL-чанков OW/V6 против исходной геометрии. Это копия,
сделанная после первого входа владельца. В отдельном скопированном ciphertext
изменён один байт с сохранением размера: настоящий SSH-поток исправил копию,
повтор передал0 архивов. Основные сохранённые копии не повреждались.
Тестовый plaintext после проверки удалён. Полный запуск восстановленного
второго auth/Minecraft и точный RTO этой проверкой не измерялись.

Код: `ops/home-server/backup_pc.py`, `world_backup_stream.py`, `auth_backup.py`,
`backup_exchange.py`, `verify_restore.py`. Восстанавливать только в новом
приватном каталоге; не указывать живой data. Перед аварийным переключением
проверить DB/UUID, закреплённые версии, прежние ключи и права10001 для auth /
1000 для Minecraft. Не назначать OP по введённому клиентом имени.

текстом в лог или state. Auth-архив также включает только относящиеся к
EREZCRAFT FRP server key/token/certificate, vhosts и service definitions.
Текущая полная репетиция восстановила **26 auth/infrastructure файлов и160
файлов серверной конфигурации**, проверила manifest hashes, UUID владельца/OP4,
whitelist, FRP TLS identity и12 FULL-чанков OW/V6. Тестовый plaintext удалён.
На VPS сохраняемых backup-архивов по-прежнему нет. Конфигурация восстанавливается
выборочно с правильными правами; старые общие firewall/SNI tables автоматически
поверх действующих сервисов не применяются.

## Очередь дальнейшей предгенерации

Подготовлена последовательная очередь: `interstice:islands_v6`, затем
`minecraft:overworld`; square center0,0, radius2048блоков, без world border,
trim/delete или архивных/ship-storage измерений. До запуска повторно прочитан
настоящий сохранённый generator V6/revision6. Предыдущие4225FULL каждого мира
сохраняются; готовые DH LOD не равны числу FULL-чанков.

`/opt/minecraft/erezcraft/pregen_control.py`, `pregen-state.json` и отдельный
cron EREZCRAFT pregen управляют только этой очередью. Пока игроки онлайн,
новая генерация приостановлена; опрос примерно раз10сек. Пауза также при
MSPT>40, свободном диске<10GiB или MemAvailable<2GiB; повтор после180сек.
После перезапуска JVM требуется осмотр checkpoint оператором, автоматическое
отсутствие задачи не выдаётся за успешное завершение. Для ручной остановки
сначала убрать **только** cron с меткой EREZCRAFT pregen, затем `chunky pause
interstice:islands_v6` / `chunky pause minecraft:overworld` через внутренний RCON.
Фактический старт и наблюдаемое продвижение записываются отдельным receipt.
