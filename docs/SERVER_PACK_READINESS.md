# Серверный EREZCRAFT: качество, предгенерация и модули

Актуальная проверенная основа и связь с собственным лаунчером:
[LAUNCHER_INTEGRATION.md](LAUNCHER_INTEGRATION.md). Interstice0.7.0-preview.3,
36 клиентских/34 серверных JAR, DH включён, startup и малый pregen/cold пройдены.
Default клиента10ГБ/Java21 ZGC. По последнему решению владельца реальные
нагрузочные замеры выполнять на целевом сервере; локальные цифры не переносить.

Последние требования владельца: около10 одновременных игроков,4 ядра и
20ГБ RAM; возможное расширение CPU. Это цель нагрузки, **не измеренная
поддерживаемая ёмкость**. Точный CPU/диск/производственный адрес текущие
файлы не подтверждают. Приоритет — стабильность, сохранность и связная
техномагия, а не максимально большой набор непроверенных JAR.

## Состав

ME-система — **Applied Energistics2**. Промышленность в духе IC —
**Modern Industrialization**, вместе с Mekanism для поздней химии/энергии.
Create/Aeronautics/Sable, Ars Nouveau и Interstice образуют общую цепочку.
Ключевые ступени техники и магии зависят друг от друга; общие материалы,
обработка и квесты не должны образовывать круговые рецепты.

Отдельный большой блок стройки/интерьеров: Chipped, FramedBlocks,
Handcrafted, Another Furniture, Macaw's Furniture/Doors/Windows/Roofs/Lights,
Rechiseled с интеграцией Create, Supplementaries и Amendments.
Карта — Xaero's Minimap + World Map. Могилы — You're in Grave Danger.
Точные версии, оригинальные хеши и библиотеки:
`distribution/server-foundation.lock.json`.

Полный поиск Modrinth по Create для целевых facets прошёл1760 результатов;
пул содержит1147 кандидатов с Create в названии и22 строительных кандидата.
`distribution/create-building-catalog.json` — **каталог исследования**, не
список1147 уже совместимых/установленных модов. CurseForge-only проекты,
аддоны с другим названием, зависимости на конкретный Create, пересечения
mod IDs и конфликты всё ещё проверяются. Требование широкого набора аддонов
сохранено; непроверенные варианты не должны попадать в серверный релиз.

## Клиентская красота и измерение

Кандидат шейдерного профиля: Iris1.8.12 + требуемый им Sodium0.6.13,
Complementary Reimagined r5.9.3, DH3.3.3. Это отдельный клиентский профиль,
его **нельзя считать проверенным** только по описанию поддержки DH.
У Aeronautics автором отмечены визуальные проблемы с Iris.

В V6 отдельно проверить чёрное небо/постоянную ночь, цвета обоих токсинов,
туман, листву, LOD-границы и движущийся корабль. Shader water displacement
не должен менять принятую геометрию океанов или превращать токсин в воду.
Миникарта должна выбирать полезный слой под верхним морем/оболочкой,
маркеры V5/V6 должны оставаться разделёнными.

Могилы требуют реальных death/cold-тестов с надетыми рюкзаками54/72/84,
внутренними компонентами, void-защитой84 и серверным правом возврата.
Положение могилы над токсином/в пустоте должно быть достижимым; сохранность
и отсутствие дублирования важнее обычной установки vanilla inventory grave.

## До допуска игроков

Предгенерация включена в запускную процедуру по прямому поручению владельца.
Сначала фиксируются финальный lock, seed, worldgen/конфиги/датапаки; после
этого создаются нужные **FULL-чанки и сохраняются на диске**. Не держать весь
район forced chunks в RAM. Строительные моды/руды, добавленные после
предгенерации, не появятся автоматически в уже созданных чанках.

Инструмент — Chunky1.4.23, официальный мод NeoForge1.21.1. Регионы выбираются
по игровому масштабу и замеру cps/диска на ограниченном тестовом районе.
Производственный radius пока не назначен; рост радиуса увеличивает площадь
квадратично. Все пользовательские регионы остаются на месте, trim/delete
не используются.

Основные цели: `minecraft:overworld` и **`interstice:islands_v6`**.
Nether/End — отдельно по реальной игровой необходимости. Не выбирать
вместо V6 `islands_v5` и не обходить автоматически архивные/виртуальные
Sable storage или лабораторные измерения.

Пример команд после подтверждения конкретного radius и dimension:

```text
chunky world interstice:islands_v6
chunky shape circle
chunky center 0 0
chunky radius <согласованный_радиус_в_блоках>
chunky start
chunky progress
```

Параллельно не запускать несколько тяжёлых измерений и независимую массовую
DH-генерацию. Готовые FULL-регионы и готовые DH LOD — разные артефакты:
после сохранения отдельно проверить LOD-пробелы и производительность.
Пауза/продолжение Chunky сохраняют процесс, а штатный stop и отдельный cold
запуск подтверждают, что результат действительно записан.

Отдельный план допуска/метрик: `distribution/server-readiness-plan.json`.
Короткие стартовые кандидаты для замера: view6, simulation4, один DH worker,
одна задача мира. Heap12ГБ — кандидат для исходного замера, не доказанный
оптимум. Не переносить измерения мощного локального ПК на4 серверных ядра.

## Факты проверок

- Первый Create/Aeronautics/Sable/DH client startup прошёл.
- Расширенный клиент с31 компонентом прошёл после добавления фактически
  обязательных Curios/GeckoLib для Ars: каталог API не перечислял их.
- Dedicated boot выявил ранний вызов ChunkyProvider из DH3.3.3 до
  инициализации Chunky1.4.23. Подготовлен условный `DhChunkyInitializationMixin`,
  который откладывает только подписку до реального готового provider.
  Результат повторных проверок читать в актуальных протоколах.
- Шейдеры, реальный полёт, ME-автокрафт, могилы, рецепты общей прогрессии,
  предгенерация и ёмкость10 игроков не следуют из startup и остаются gate.
- Прежний dedicated-тест лебёдки выявил vanilla anti-flight kick после24/23
  тиков движения.200 тиков/latency/cold dedicated пока не приняты.

Профили и отрицательные результаты находятся в `.verification`.
Рабочие пользовательские игры не закрывались для расширения модпака;
расширенный состав не установлен поверх их сохранений.
