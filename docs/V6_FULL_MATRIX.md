# V6: шесть настоящих FULL-миров

Новый `TensionRealmVisualSmoke` подключается только отдельным root run с
`interstice.tensionRealmSmoke=true`. Профиль обязан лежать в `.verification`.
Результат — `v6-full-matrix-validation.json`; скриншоты находятся в стандартном
`screenshots`, voxel-сечения — в `voxel-sections/seed-…/`.

Одна клиентская JVM по очереди создаёт шесть новых сохранений с точными seed:
`0`, `1`, `-1`, `20261006`, `76198123`, `4294967297`. Источник данных — реальные
`ServerLevel`, настоящий `RandomState` каждого сервера и FULL-чанки измерения
`interstice:islands_v6`. Seed сохранений не меняется; синтетическая матрица предыдущих
NOISE GameTests не выдаётся за эту проверку. `CURRENT_WORLD` не переключается: камеры
явно переносят только тестового Creative игрока в V6.

После каждого мира выполняется `NativeChunkSettler`, затем штатная последовательность
`ClientLevel.disconnect()` и `Minecraft.disconnect(new TitleScreen())`. Первая операция
закрывает connection; вторая ждёт остановки integrated server и сбрасывает level/player/registries.
`clearClientLevel` очищает только клиент и не заменяет её. Отдельный guard защищает
helper от повторного входа при внутренних render ticks штатного disconnect.

## Объявленные окна

| Проверка | Границы |
|---|---|
| Климат/земля четырёх биомов | Чебышёвский радиус2048; сетка64, offset7; до8 численных dry-land кандидатов на биом |
| Реальная земля | Первый подходящий FULL чанк каждого биома; собственный16×16 interior, без расчистки |
| Геометрия/лес | Четыре49×49 FULL плота, halo1; две настоящие соседние FULL-колонки чанков на биом |
| Неотобранный FULL контроль | Origin чанки(-1,-1),(-1,0),(0,-1),(0,0) и пары(47,-32)/(48,-32),(-48,31)/(-47,31) |
| Стоячие пещерные маршруты |49×49 вокруг выбранного stone-vaults; Y35..205; feet/head AIR, сухая прочная опора, горизонтальные шаги±1 |
| Берег | Радиус512 от выбранного garden point, сетка16;≤24 фактических FULL центра и их объявленный halo18 |
| Постройки/мембрана | До32 кандидатов RealmStructuresV5, отсортированных по расстоянию, anchor origin в радиусе2048 |

Пещерный граф различает открытые своды и вырезанные туннели: для последних настоящий
воздушный node был породой в каноническом uncarved поле и воздухом в carved поле.
Доступность требует связного dry walking пути от настоящей открытой поверхности.
Компоненты без такого пути отдельно делятся на замкнутые внутри окна и обрезанные
границей; глобальная недоступность за пределами окна не заявляется. Камера и маршрут
выбранной пещеры записываются с реальными координатами. Наличие воздуха не заменяет
эту проверку.

Геология/жидкости FULL сравниваются с каноническими material columns после surface.
Замены грунтом, растениями и структурами считаются как изменения стадии; это
не повторное доказательство raw NOISE равенства. Shell, upper sea и clearance
проверяются непосредственно по FULL блокам. Hash записывается для реальных origin
и соседних чанков; конечный static snapshot явно отмечает уже выгруженные чанки.
Отдельный холодный JVM-перезапуск остаётся следующей проверкой root.

V5/V6 пары готовятся отдельно после этой матрицы. Для seed20261006 сохраняется
принятый V5 manifest с forest-eye(258.5,72,-573.5) и остальными baseline ракурсами.
Оба сравнения используют выбранную общую палитру и одинаковые FOV/gamma/AO/resolution.
Боковой обзор можно снять из одной абсолютной свободной камеры в обеих ревизиях;
eye-height ракурсы используют действительную землю каждой ревизии и явно записывают
разницу координат. Камеру не расчищают и V5 мир не заменяют тестовым V6.

Ресурсы считаются только в перечисленных фактически загруженных окнах: серебряные
блоки, естественные культуры, плоды и реальные контейнеры с назначенным observation
post loot table. Они не открываются и не заполняются тестом. Назначенный природный
контейнер с гарантированным coupler entry — источник добычи, а не предмет, уже
полученный игроком. Отсутствующий ресурс/биом/лес/пещера записывается как отсутствие,
границы и бюджеты автоматически не расширяются.

## Клиент и нагрузка

На seed планируются восемь естественных ракурсов: четыре biome eye views, боковой
силуэт ash, forest eye, доступная пещера и берег. Каждый имеет основной dark и
отдельный NV кадр; ожидаемый полный набор —96 PNG. Если доступной пещеры/берега/леса
нет, fallback surface кадр подписывается `unavailable`, а критерий остаётся проваленным.
Ни одного блока для ракурса не удаляют. Дополнительные49×256 сечения PNG/JSON строятся
из фактически загруженных voxel states, а не из формулы density или изменённой сцены.

Настройки заново фиксируются для каждого нового мира:1280×720, FOV70, gamma0.5,
Fancy, AO, render distance4, simulation distance5. Random ticks отключены для
инспекции исходной геометрии. После FULL quiescence настоящий integrated Creative
клиент наблюдается200 серверных тиков CALM и200 тиков реального SURGE. Во время
фотосъёмки симуляция временно заморожена и удерживается CALM; перед закрытием
возвращаются обычные тики. Это не Survival и не сетевой dedicated тест.

CPU server thread и wall duration измеряются от highest Pre до lowest Post, включая
остальные NeoForge обработчики внутри этой пары. p50/p95/p99/max и отдельно calm/
surge публикуются без усечения. Интервалы Pre→Pre учитывают задержки между тиками,
в том числе scripted mailbox preparation. Время запроса каждого настоящего FULL
чанка выводится отдельно. Порог p95 CPU50ms относится только к этой объявленной
нагрузке одного клиента; четыре/восемь CPU equivalents, обычное исследование игроком,
два реальных сетевых клиента и холодная/прогретая повторная генерация здесь не закрыты.

Промежуточный JSON сохраняется при смене seed/stage и после кадров; stdout содержит
каждую подготовленную FULL точку и heartbeat каждые200 client ticks. Общее ограничение
матрицы90 минут, очистка выполняется штатно даже при провале отдельного мира.

Текущий статус: исходники прошли отдельный JDK21 `javac`; нативная матрица ещё не
выполнялась. Эти инструкции не являются её результатом. Root подключает Gradle/
verifier hook, запускает новый профиль и оценивает `passed` вместе с явным списком
`missing_in_declared_windows` каждого seed.
Ресурсный census читает `getBlockEntitiesPos()` — объединение live и pending worldgen
NBT — и не открывает контейнеры. `getBlockEntities().values()` был недостаточен:
первый partial run seed0 сообщил0 контейнеров, хотя RO-анализ32 сохранённых MCA
кандидатов обнаружил15 природных loot barrels, включая4 observation posts. Это ошибка
наблюдателя; размещение и budget32 не изменялись. Первый run также потребовал штатного
закрытия его собственного connection после недостающего первого шага disconnect;
он сохранён как failed/partial и не считается шестимировой приёмкой.
