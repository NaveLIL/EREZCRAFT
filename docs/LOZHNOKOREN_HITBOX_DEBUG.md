# Ложнокорень: рамки F3+B

28.10.2026, локальный кандидат preview.46-root-hitbox-debug.

Владелец заметил зелёные рамки составных частей, которые быстро пролетают снизу вверх, при этом удары по существу проходят правильно. Проверен настоящий EntityRenderDispatcher NeoForge21.1.252: зелёные рамки multipart-сущностей рисуются по интерполяции PartEntity.xOld/yOld/zOld → текущая позиция. В refreshSections обновлялись только xo/yo/zo; части самостоятельно не тикают, поэтому нужная отрисовщику история оставалась нулевой. Каждый игровой тик интерполяция начиналась от начала координат.

Это ошибка отладочного отображения. Текущие AABB частей, проверка попаданий, общие здоровье/броня и физическое положение не используют эту ошибочную историю. Она не свидетельствует о повреждении мира. Исправление обновляет обе группы предыдущих координат; при первом размещении и скачке более8 блоков история начинается с новой позиции, без визуального пролёта через мир.

## Проверка

18 обязательных GameTests прошли, включая пять промежуточных кадров при обычном перемещении и сброс истории после телепортации. Полный клиент дополнительно вызывает настоящий приватный renderHitbox на partialTick=0/0.25/0.5/0.75/1, проверяет вершины рамок относительно существа до/после reload и во время поворота. Режим F3+B включён на диагностических кадрах.

Полная игровая проверка завершена: PASS,351,312с,106 модов/DH, настоящая V6, штатное сохранение и выход. Настоящий renderHitbox проверен до/после reload и при повороте; рамки остаются около существа. Удар снял21,64801 здоровья с цели, изгиб35° принят сервером и клиентом.1558 ресурсов/data и581 старый класс побайтно прежние; изменились только Lozhnokoren и его Section. Анимация45 и существующие правила попадания сохранены. JAR SHA256:67cd522e8581fe624117e803b155c84852eb802644cbf4f3de44fbd0cd9dc7f5.

Сервер не обновлялся. Предыдущие профили владельца lk44n2 и lk45n3 сохранены; автоматические прогоны использовали отдельные lk46n1/lk46n2. После завершения lk46n2 передан владельцу; больше не использовать его для автоматических изменений.

Первый native-прогон остановлен на ошибке тестового счётчика: он применял ограничения нормалей поверхностей к отладочным линиям. Измеренный вертикальный диапазон рамок уже был правильным:0..2,25 блока относительно моба. Для повторного прогона проверка нормалей поверхностей отделена; проверяются конечные вершины линий, их диапазон и промежуточные кадры. Этот первый прогон не помечен успешным.
