## Воспроизведённые причины

0.4.3–0.4.5 проверяли Java/NeoForge processors, но полный запуск оставался
проверкой владельца. В отдельной папке с кириллицей воспроизведены два ранних
сбоя того же кода подготовки клиента:

- JPLIS `AddToSystemClassLoaderSearch`103: 8.3 alias агента EREZ ID недостаточен,
  JVM возвращается к имени с кириллицей. Оригинальный pinned authlib-injector
  теперь проверяется/устанавливается в реальный ASCII-кеш пользователя рядом
  с Java/natives. Его байты, SHA, auth URLs и проверка подписей скинов прежние.
- NeoForge BootstrapLauncher видел один JAR под разными именами в module path
  и classpath: короткое имя файла против Maven suffix с полным ASCII-именем.
  Short alias теперь выбирается для последнего Unicode-предка, а ASCII-суффикс
  сохраняется. Пути совпадают; библиотеки не переезжают и не перепаковываются.

Учтена provenance локального PortableMC patch; original_source_sha256 прежний.
Новые regression проверяют реальный ASCII-каталог агента и равенство module/
class пути. AppLocker не отключался; свежих deny событий при диагностике не было.

## Диагностика

Раньше stdout/stderr Java отбрасывались, и до инициализации Minecraft логов
не было. Теперь `logs/launcher-process.log` захватывает оба потока с раннего
старта, предыдущий запуск остаётся в `launcher-process.previous.log`.
Каждый ограничен4МиБ плюс заголовок/маркер; после достижения лимита pipes
продолжают опустошаться. Команда/Session не записываются, передаваемый токен
маскируется даже между границами чтения. Тесты проверяют redaction и отсутствие
блокировки при большом выводе. `logs/launcher-exit.json` содержит код завершения.
Ошибка игры показана красным с кодом и названием файла, вместо зелёного notice.

## Отключение контроля RAM

**Настройки → Игнорировать проверку свободной памяти**. По умолчанию выключено.
Предупреждение объясняет риск зависаний/вылетов Minecraft и системы. При явном
включении снимаются frontend/backend блокировка по свободной RAM, повторная
проверка перед spawn и диалог подтверждения лимита. Сам лимит -Xmx и прежние
границы2–16ГиБ сохраняются; автоматический подбор остаётся доступным.

Выбор хранится в `.erezcraft/memory-policy.json`; старый preferences.json
не получает новых полей, поэтому откат лаунчера не сбрасывает прежний RAM.
Старые IPC вызовы без нового аргумента сохраняют выбор, явное выключение
возвращает проверки. Неверный/отсутствующий policy включает обычные проверки.
На ПК владельца отключение автоматически не включалось.
