# Проверки после публикации alpha.21

28.10.2026. По поручению владельца проведены автоматически. Рабочий сервер не перезапускался и его мир не использовался в сценах. Резервные копии не создавались.

## Настоящая доставка HTTPS

Штатный Installer::synchronize установил 20→21 в новой служебной папке: 89 файлов проверено, две замены (собственный JAR и маркер), один старый JAR в карантине. Изменённый байт при сохранённых размере и mtime был обнаружен; скачивание восстановило JAR. Повтор: 89 проверено / 0 замен / 0 карантинов. Тестовый world, options и личная настройка UI побайтно сохранены. Фикстура: `D:/repos/erezcraft/.local/verification/blade-delivery-20261028/delivery-verification.json`.

## Состояние существ между JVM

Две настоящие GameTest JVM выполнили по два теста. Сводник сохранил ранения, но сбросил старую цель/позицию/боевую память. Паук сохранил ранения, разновидность LURKER, высоту 1,7 и остаток рывка 37 тиков; скрытая цель/наблюдение сброшены. PID создателя и загрузчика различаются. Это чтение entity NBT между процессами, не приёмка полного перезапуска региона/мира. Искусственный GameTestServer использует оговорённое исключение без DH.

## Сеть: полноценный клиент и отдельный dedicated server

На отдельном контейнере развёрнуты те же 67 серверных JAR плюс только служебный мод сцены. Клиент загрузил полный пакет и DH; встроенного сервера в клиенте не было. Сцена размещена в настоящей V6, а не в плоском измерении.

Первоначальное подключение через обычный опубликованный Docker-порт не работало: внутри контейнера status-запрос проходил, через порт хоста сбрасывался; внутренний IP контейнера также был недоступен с хоста. Причина конкретного ограничения Docker-сети не устанавливалась и глобальная сеть не менялась. Для проверки использован подтверждённый маршрут localhost TCP → SSH exec → TCP loopback внутри контейнера. Рабочий сервер через обычный публичный адрес независимо ответил на status-запрос с протоколом 767 / MC1.21.1 / max10.

Обе стороны записали серии: 360 положений, 359 приращений. Сводник на сервере сохранял фазу CHASE и действительную цель-игрока все 360 контрольных тиков.

| Наблюдение | Сводник | Плевальщик | Ванильный зомби |
|---|---:|---:|---:|
| Сервер: пройдено, блоки | 55,26 | 73,23 | 40,83 |
| Сервер: самая длинная остановка, тики | 0 | 3 | 0 |
| Клиент: пройдено, блоки | 62,65 | 68,62 | 36,34 |
| Клиент: самая длинная остановка, тики | 1 | 1 | 4 |

Серверная и клиентская выборки начинаются в разное время; расстояния между строками не являются оценкой потери движения. У плевальщика AI самостоятельно выбирал цель: сохранение первоначально заданного неуязвимого зомби не утверждается. Позднее неуязвимость этого служебного зомби была снята; операция записана отдельно. Это изменение фикстуры, не игрового кода.

Сорок кадров сохранены, но слишком тёмные/неудачно кадрированы для визуальной приёмки походки. Результат сети основан на координатах, не на этих кадрах. Сетевая выборка содержит пакетную неравномерность; она не доказывает идеальную визуальную плавность.

## Границы и завершение

Подготовленная сцена не закрывает естественный Survival, баланс и ёмкость на 10 игроков. Изолированный сервер использовал offline-идентичность; положительный вход EREZ ID на рабочий сервер не проверен. UDP кораблей Sable и голосовой чат не принимались этим TCP-тестом. Полный регион/world reload и визуальная оценка походки остаются отдельными проверками.

Служебный сервер остановлен, TCP-прокси закрыт, локальных игровых JVM не осталось. Рабочий сервер healthy. JAR alpha.21 не менялся; исправлены только служебные проверки. [Машинный отчёт](verification/ALPHA21_POSTRELEASE_TESTS.json).
