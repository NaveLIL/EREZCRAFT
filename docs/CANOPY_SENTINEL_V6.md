# Кроновый страж: изолированный этап F

Подготовлен новый вид для венечных крон. Его регистрация, точный callback сбора и
нативная приёмка ещё не подключены; текущие V1–V5 и принятая галерея палитр не менялись.
Пять новых main-классов и подготовленные GameTests компилируются отдельно с JDK21
и локальным classpath NeoForge21.1.252. Это проверка API, а не игрового поведения.
Подготовлено15 GameTests с отдельными batch; они пока не запускались.

## Силуэт и материалы

Низкое кубическое тело, отдельная морда, два вытянутых уха, четыре лапы и широкий
трёхчастный хвост образуют силуэт небольшого обитателя кроны. Модель содержит14
обычных кубов. Тело использует готовую `garden/crown_log`, глаза — `gloomcrown_log`,
хвост — `garden/crown_leaves` отдельным cutout проходом. Новых PNG, перерисовки,
масштабирования, нового атласа и изображений ImageGen нет.

Предупреждение меняет силуэт: хвост поднимается, уши расходятся, движение прекращается.
Звук ссылается на штатный FOX_SCREECH; новые аудиофайлы не распространяются. Спокойное
состояние имеет лёгкое движение хвоста, преследование — более быстрые движения лап.
Обычная тёмная атмосфера не заменяется дополнительным свечением существа.

## Контракт поведения

| Свойство | Первая реализация |
|---|---|
| Размер / здоровье | 0.58×0.72 блока;12 HP |
| Скорость / урон | 0.27; обычная melee атака2 HP, интервал20 тиков |
| Дом | Воздушная позиция ног над настоящим crown leaf, distance<7 |
| Территория | Радиус20 вокруг дома; внимание только к игроку в полосе±8 по высоте |
| Предупреждение | 24 настоящих AI тика без атаки; видимый хвост/уши и штатный звук |
| Выбор цели | Ближайший подходящий игрок; детерминированная UUID ничья |
| Смена цели | Не раньше40 тиков; только существенно более близкий игрок; новое полное предупреждение |
| Преследование | До160 тиков; прекращается при выходе игрока или существа за радиус24 |
| Отсутствие пути |40 тиков неуспешной навигации → возврат |
| Спокойный промежуток |200 тиков после возврата; отсутствие новых атак |
| Мирная альтернатива | Приседающий игрок не выбирается; приседание текущей цели снимает конфликт |
| Невалидная цель | Смерть, другое измерение, удаление/отключение, creative/spectator → возврат |
| Срубленная крона | Обычная гравитация, поиск загруженного нижнего сухого грунта, тихое наземное состояние |

Полноценная навигация по каждой ветке не заявлена. Используется штатный ground
navigation с шагом1; пути не создают новые блоки, не телепортируют сущность и не
отключают гравитацию. При невозможном возврате страж после естественного приземления
может закрепиться в спокойном наземном доме. Потерявший крону житель не начинает
территориально атаковать обычный наземный маршрут. В новом измерении сохранённые
координаты прежнего дома не превращаются в цель навигации.

Сохраняются родной Entity UUID, координаты и измерение дома, признак живой кроны,
выбранный target UUID, фаза, оставшееся предупреждение/cooldown и прошедшие сроки
удержания/преследования/возврата. После загрузки target заново разрешается в текущем
серверном измерении. Отсутствующий игрок не остаётся невидимой целью. Интервалы
ограничиваются при загрузке; отсутствующая цель или пустое предупреждение не дают
немедленную атаку.

## Естественное заселение

`RealmFauna` требует настоящий `IslandChunkGenerator` revision6. Ни legacy-измерения,
ни обычный мир автоматически не заселяются. Chunk load и явный сигнал завершённого
V6 леса лишь добавляют кандидата в bounded очередь; создание существа не выполняется
на потоке генерации.

- Максимум64 ожидающих чанка, задержка40 тиков, срок ожидания240 тиков.
- Обрабатывается один кандидат на измерение каждые20 тиков.
- Детерминированно подходит четверть чанков; это ещё не численная приёмка плотности.
- Инспектируется только реальный loaded FULL `getChunkNow`; `getChunk()` отсутствует.
- Требуются≥16 актуальных crown leaves и≥1 настоящий crown fruit; обычная листва не подходит.
- Дом рядом с плодом стоит на поддержанном crown leaf, имеет свободные ноги/голову.
- Максимум одна успешная первая добавленная сущность на чанк и локальный cap2 в области48 блоков.
- Точный successful spawn записывается в SavedData. Выгрузка/перезагрузка, рубка и убийство
  не открывают этот чанк повторно и не создают дубликат.
- Проверка позиции и finalize проходят через штатные NeoForge EventHooks; отменённое
  сторонним обработчиком добавление не записывается как состоявшееся заселение.

Полный scan имеет фиксированный объём одного16×16 чанка между морем и maxLand.
Реальное время scan и влияние живых стражей на серверный тик пока не измерены.
Проверенный код постановки в очередь не доказывает присутствие вида в естественном
мире: это отдельная нативная приёмка на заранее выбранных seed.

## Подключение root после C stable

1. В основном mod constructor вызвать `RealmFauna.register(modBus)`; он подключит
   entity registry, attributes, chunk-load и bounded server-tick ecology.
2. В client-only ветке добавить два mod-bus listener:
   `FaunaClient::registerLayers` и `FaunaClient::registerRenderers`.
3. После успешного AGE3→0 и выдачи плода в `CrownFruitBlock` вызвать
   `RealmFauna.notifyFruitHarvest(player,pos)`. Предварительный RightClick event
   не используется: он не может надёжно приписать успешный сбор при нескольких игроках.
4. При необходимости вызвать `RealmFauna.scheduleNaturalSpawn(level,chunkPos)` после
   реального завершения V6 леса; основной load hook уже обеспечивает повторное наблюдение.
5. Подключить `interstice_fauna` GameTest namespace и отдельную копию `empty` шаблона.
   Текущие prepared тесты явно инициализируют дом, не обещают natural spawn или настоящую сеть.
6. Объединить `tools/v6_fauna_lang.json` с локализациями. Новый entity loot table пуст:
   охота не является возобновляемым источником плодов или обходом местного хозяйства.

Ни одного из этих изменений общего кода текущий изолированный этап не выполняет.
Новый package не имеет автоматического EventBusSubscriber.

## Доказательства, которые ещё нужны

После подключения выполняются подготовленные AI/NBT GameTests, затем естественное
заселение V6, обычные тёмные кадры силуэта/предупреждения, уничтожение настоящего
дерева, отсутствие пути и отдельная JVM перезапуска. С двумя/тремя настоящими игроками
проверяются смена цели, одновременный сбор, смерть, переход измерения и disconnect.
Mock connection не заменяет эти сетевые сценарии. Влияние обычного прилива сохраняется
и отдельно проверяется; новая иммунность от морей или глобальной физики не добавляется.

Этап F и вся V6 пока не объявляются принятыми. Исходники/компиляция — выполнены;
root integration, исполняемые тесты, естественный чанк, клиент, холодное сохранение,
нагрузка и настоящая сеть — открытые критерии.
