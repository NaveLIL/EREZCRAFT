# M03 — общий профиль геометрии морей и сетевая синхронизация

Дата: 07.10.2026. Статус: **проверено в пределах M03**. Исходная точка — `55e2c06e329658258fb51645a7df88df6677a36e` (M01).

## Что реализовано

1. **Модель `GeometryProfile` (`pro.erez.interstice.geometry.GeometryProfile`)**:
   - Версионированный record (`version=1`, `minY`, `height`, `lowerSeaTop`, `upperReference`, `clearance`).
   - Валидация section-alignment (кратность 16) и вписывания в пределы Minecraft.
   - Декодирование через `flatXmap` для возврата понятных ошибок кодека вместо исключений конструктора.
   - Профиль `LEGACY`: `(1, 0, 128, 34, 94, 6)`.
   - Сериализация через `FriendlyByteBuf` и Mojang Codec.

2. **Сетевая синхронизация конфигурационной фазы (`GeometrySync`)**:
   - Регистрация payload `geometry_profiles` и задачи конфигурации `RegisterConfigurationTasksEvent` / `ICustomConfigurationTask` (NeoForge 1.21.1).
   - Сервер передаёт актуальные профили измерений до создания `ClientLevel`.
   - Клиент подтверждает получение пакетом `geometry_ack`, завершая задачу конфигурации.

3. **Интерфейс `GeometryView` и Mixin-проброс**:
   - `ClientLevelGeometryMixin`: привязывает профиль к уровню при инициализации клиента.
   - `RenderRegionGeometryMixin` и `NavigationRegionGeometryMixin`: делегируют получение геометрии из соответствующего уровня, исключая обращение к глобальному клиенту.

4. **Единый источник истины геометрии**:
   - `SeaSurface`: переведён на приём `GeometryProfile` для всех вычислений (`vertexHeight`, `heightAt`, `cellMinimum`, `minimumUnderBox`, `thickness`, `pickingShape`).
   - `FluidContact`: точный расчёт перекрытия AABB сущностей и инвертированного погружения глаз с учётом профиля.
   - `FluidClient`: рендеринг океана с динамическим получением профиля через `GeometryProfiles.get(world)`.
   - `LightBucketItem`: слив в удерживаемый океан без разрушения формы вокселей.
   - `OceanLiquidBlock`: сохранение статической формы монолита без тиков растекания.
