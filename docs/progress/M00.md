## Воспроизведение в новой копии

Следующий сценарий предназначен для нового повторного прогона; уже использованные тестовые каталоги не очищаются. Локальный JDK должен существовать, зависимости должны быть доступны через кеш или сеть. `mktemp` выделяет новое место для checkout; исходные пользовательские миры не затрагиваются.

```sh
set -eu
export JAVA_HOME=/Users/dimon/Library/Java/JavaVirtualMachines/jbr-21.0.11/Contents/Home
export PATH="$JAVA_HOME/bin:$PATH"
M00_REPRO_PARENT="$(mktemp -d /tmp/interstice-m00-repro.XXXXXX)"
git clone --branch m00-verified-20261006 \
  /Users/dimon/Documents/Minecraft/.m00/20261006-baseline/verified-source.bundle \
  "$M00_REPRO_PARENT/project"
cd "$M00_REPRO_PARENT/project"
java -version
./gradlew --no-daemon --console=plain --version
./gradlew --no-daemon --console=plain build
./gradlew --no-daemon --console=plain runGameTestServer
mkdir -p build/island-smoke
printf 'onboardAccessibility:false\n' > build/island-smoke/options.txt
./gradlew --no-daemon --console=plain runIslandSmoke
python3 - <<'PY'
import json
from pathlib import Path
report = json.loads(Path('build/island-smoke/island-validation.json').read_text())
print(json.dumps(report, ensure_ascii=False, indent=2))
if report.get('passed') is not True or report.get('reason') != 'completed':
    raise SystemExit('M00 smoke failed; see island-validation.json and client log')
PY
```

Игровой smoke требует графической сессии. В фактических прогонах команды оборачивались `run_check.py`; например, `M00_WORKTREE=/Users/dimon/Documents/Minecraft/.m00/20261006-baseline/verification-worktree python3 /Users/dimon/Documents/Minecraft/.m00/20261006-baseline/run_check.py verified-smoke ./gradlew --no-daemon --console=plain runIslandSmoke`. Повторно использовать эту метку нельзя: обёртка откажется перезаписывать доказательства.

## Ошибки и разграничение причин

1. **Дефект подготовки исходного smoke, исправлен:** тест фиксировал позицию при появлении клиента до завершения `ReceivingLevelScreen`. В `diagnostic-smoke.log:151` ожидаемая позиция ошибочно сохранена как `(8.5, 65.0, 8.5)` на первом клиентском тике. В строке 154 сервер сохраняет настоящую позицию `(-216.5, 68.0, 468.5)`; в строках 175–176 клиент и сервер после возврата находятся именно там. Сбой был в преждевременном эталоне теста, а не в наблюдаемом возврате игрока. Коммит `4eacf74` ожидает закрытия экрана загрузки перед снимком; после него прежний набор проверок проходит. Диагностическая инструментализация не включена в основной код.
2. **Вспомогательный Python:** системный Python 3.9.6 не имеет `hashlib.file_digest`; первая попытка создания манифеста остановилась с `AttributeError`. Манифест успешно создан потоковым SHA-256, совместимым с этой версией. Это проблема диагностического скрипта, не Java-проекта.
3. **Настройка окружения:** первый запуск свежего профиля требует обработки экрана специальных возможностей. Для финального прогона это явно сделано через `onboardAccessibility:false` в отдельном профиле. Связь задержки первого запуска с каким-либо ручным действием не заявляется.
4. **Предупреждения:** build сообщает deprecated API/Gradle features; это не остановило сборку. Обновление Gradle или игрового стека не входило в M00.
5. **Оставшееся ограничение тестовой обвязки:** Gradle `runIslandSmoke` возвращает 0 и при отрицательном JSON. Это сохранённое поведение; воспроизводимый сценарий выше дополнительно проверяет JSON и возвращает ошибку при отрицательном результате. Для будущего CI этот шаг обязателен.

## Непроверенные сценарии, приёмка и готовность следующих задач

Обязательные проверки M00 выполнены; технических блокеров для следующей отдельно порученной задачи не осталось. Полная безкомандная экспедиция M12, новая геометрия, инфекция, многопользовательский клиентский сценарий, длительная нагрузка и художественная приёмка относятся к следующим задачам и здесь не заявляются. GameTestServer не подменяет проверку сетевой экспедиции с реальными клиентами.

По таблице зависимостей `AI_TASKS.md` задачи **M01 и M03 готовы к отдельному поручению после M00, но не начаты**. M01 предстоит самостоятельно подтвердить кандидат инфекции и его зависимости в изолированном профиле; M03 — выделить профиль геометрии с сохранением текущего поведения. Эти работы не выполнялись автоматически. Решение владельца о принятии внешнего вида и игрового ощущения остаётся открытым и не является заявленным результатом M00.
